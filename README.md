# Детекция ботов на Авито

Тестовое задание Data Science Bootcamp 2026 (Classic ML): по событиям внутри суточного окна присвоить каждой `cookie_id` оценку от 0 до 1 — вероятность того, что это трафик сервиса автоматизированного сбора данных.

## Результат

| Метрика | Значение |
|---|---|
| P@R0.7 на локальной валидации | 0.35 |
| Уровень константы (доля ботов) | 0.082 |
| Baseline из quickstart | 0.1025 |

## Как запустить

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Положить выданные файлы в `data/` (`train.csv`, `test.csv`, `events.csv.gz`), открыть `solution.ipynb` и выполнить Run All. На выходе появится `submission.csv`.

- Python: 3.13
- Все случайные процессы зафиксированы (`SEED = 0`).

## Подход

### Данные и очистка

- Признаки считаются только по событиям внутри окна куки: `window_start_ts <= event_ts < window_end_ts`.
- Строки файла событий перемешаны, поэтому события сортируются по куке и времени перед расчётом пауз.
- `platform` записана в разном регистре и с синонимами (`iphone`/`ios`, `desktop`/`web` — одинаковые User-Agent). Значения приведены к трём платформам. Проверено, что разнобой в написании не связан с классом (есть у 96% людей и 99% ботов).

### Найденные утечки

- **Капча.** Все события `captcha_shown` находятся после окна наблюдения. Это информация из будущего, поэтому признаки по капче не используются.
- **Время создания куки.** Проверено, что у всех кук `cookie_created_at` раньше конца окна, поэтому возраст куки используется как признак.

### Признаки

| Группа | Признаки | Идея |
|---|---|---|
| Объём и разнообразие | `n_events`, `item_nunique`, `n_locations`, `n_queries` | парсеры делают больше действий и охватывают больше городов и запросов |
| Ритм | `gap_median` | медианная пауза у ботов ~25 с против ~59 с у людей |
| Глубина поиска | `max_page` | парсеры листают выдачу глубже |
| Типы действий | `share_*` по `event_name` | люди чаще добавляют в избранное, логинятся и листают фото |
| Возраст куки | `cookie_age_h` | часы от создания куки до начала окна |

Не используются как признаки: сырые `cookie_id`, `item_id`, даты окна (описывают «кто и когда», а не поведение) и события после окна.

### Валидация

Тест лежит позже трейна по времени, поэтому валидация тоже временная: обучение на окнах до 2026-04-17, проверка на окнах начиная с 2026-04-17. Метрика считается официальной функцией из `metric.py`.

### Журнал экспериментов

Модель: RandomForest (300 деревьев, `min_samples_leaf=3`, `random_state=0`).

| № | Шаг | P@R0.7 |
|---|---|---|
| 0 | Константа | 0.0820 |
| 1 | Baseline: `n_events`, `item_nunique` | 0.1025 |
| 2 | + ритм и глубина поиска | 0.2258 |
| 3 | + доли типов событий | 0.3019 |
| 4 | + возраст куки | 0.3500 |

## Ограничения и дальнейшие шаги

- Валидация — один временной разрез, оценка может быть шумной.
- Для кук с одним событием пауза не определена и заполняется нулём, что похоже на «очень быстрый клик».
- В планах: ритм внутри сессий, дубликаты событий, разбор `user_agent`, LightGBM, абляции по группам признаков.
